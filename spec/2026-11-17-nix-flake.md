# Spec: Install and configure omateams from this fork's own flake

## Owner decisions (from the intent approval)

- Ship the Qt fix now. Don't wait for `nixos-unstable`.
- Nix supplies first-run setting defaults only. The shell UI stays in charge
  of settings. **That decision can't be carried out as approved** (see
  "Settings" below), so this spec leaves settings to the shell for now, and
  open question 1 asks the owner to confirm.
- This lands after PR #1, so the first flake build carries the memory guard.

## Design

### Files in this repo

| File | Purpose |
|---|---|
| `flake.nix`, `flake.lock` | Inputs and outputs |
| `nix/package.nix` | The package. It moves here from the NixOS config's `pkgs/omateams/default.nix` and builds from this repo's source. |
| `nix/home.nix` | Home-manager module |
| `nix/nixos.nix` | NixOS module |

The shape follows `nixarchy-omapod`.

### Inputs

- `nixpkgs`: `nixos-unstable`. It is meant to be followed by consumers.
- `nixpkgs-qt`: a pinned nixpkgs `master` revision whose `qt6.qtwebengine` is
  `6.140.0`, which has the QTBUG-142040 fix and is already in cache.nixos.org.
  - The README tells consumers not to make it follow their nixpkgs until
    their nixpkgs has QtWebEngine 6.140.0 final or later.
  - Once `nixos-unstable` has it, a later change removes the input.

### Package (`nix/package.nix`)

- **Whole build from `nixpkgs-qt`.** The package is built with `nixpkgs-qt`'s
  `callPackage`, so stdenv, glibc and the Qt set all come from one nixpkgs.
  Mixing one nixpkgs' `qtwebengine` into another nixpkgs' build would load
  two glibc and Qt copies into one process.
- **Only `hyprland` comes from the consumer.** It is used only as a command
  on `PATH`, in a separate process, so it must match the running compositor.
  The overlay and the modules pass it in.
- **Source** is this repo, via `lib.fileset` (`host`, `ui`, `assets`,
  `manifest.json`, `preview.png`, `LICENSE`).
- **Version** is read from `manifest.json` and passed to qmake as
  `OMATEAMS_VERSION`. The host and the plugin therefore always report the
  same version, so `Service.qml:169-174` never replaces the host on a
  version mismatch.
- **Qt version assert.** The build fails unless QtWebEngine is `6.140.0`
  final or newer. Nix compares `6.140.0-rc` as greater than `6.140.0`, so the
  test compares the part before any `-` and rejects a pre-release of
  `6.140.0`:

  ```nix
  let v = qt6.qtwebengine.version; base = lib.head (lib.splitString "-" v); in
  assert lib.versionOlder "6.140.0" base || v == "6.140.0";
  ```

- **Carried over unchanged from the current package:**
  - the `Service.qml` substitutions (store `hostBinary`, `checkInstalled()`
    instead of self-install), still with `--replace-fail`, so upstream drift
    breaks the build;
  - the install layout: binary, desktop entry, icon, and the plugin payload
    without `install.sh`;
  - `qtWrapperArgs`, which puts Hyprland, libnotify, coreutils and bash on
    `PATH`;
  - the `systemd-run` scope wrapper (`MemoryHigh=12G`, `MemoryMax=16G`,
    `MemorySwapMax=0`) with its unscoped fallback when there is no user bus;
  - the install checks, plus a check that the binary's reported version
    matches the manifest.
- **The `BarWidget.qml` colour fix (#2778)** stays a build-time
  substitution, as today, because the intent rules out changes to the app's
  code.

### Settings

- **The shell never applies manifest defaults.** This shell build
  (`omarchy-edge-20261117`) copies `barWidget.defaults` into the widget
  entry (`shell.qml:1505`), but no code in the shell reads it afterwards,
  and nothing reads `schema[].defaultValue`.
  - The plugin gets only the values saved in `shell.json`.
  - `Service.qml:62-77` then falls back to hard-coded values.
  - So changing the manifest's defaults would have no effect.
- **The only other route is patching those fallbacks.** That changes
  behaviour for all users of the package and is fragile.
- **This spec therefore has no `settings` option**, and the shell UI keeps
  sole ownership of settings. If the owner wants Nix-set first-run defaults
  anyway, the spec would have to choose between:
  - patching the `Service.qml` fallbacks;
  - a home-manager activation step that writes the plugin entry into
    `shell.json` only when it is missing.

### Overlay and outputs

- `overlays.default`: `omateams = pkgsQt.callPackage ./nix/package.nix { hyprland = final.hyprland; }`,
  where `pkgsQt` is `nixpkgs-qt` for `final`'s system.
- `packages.<system>.{omateams,default}`: the same package, using
  `nixpkgs-qt`'s Hyprland.
- `apps.<system>.default`: runs it.
- `checks.<system>.package`: builds it, which runs the install checks.
- `homeManagerModules.default`: `nix/home.nix`.
- `nixosModules.default`: `nix/nixos.nix`.
- Systems: `x86_64-linux` and `aarch64-linux`.

### Home-manager module (`programs.omateams`)

- `enable`.
- `package`, which defaults to the flake package.
  - Home-manager can't tell which Hyprland the compositor runs:
    `wayland.windowManager.hyprland.package` may be null, or differ from
    NixOS's `programs.hyprland.package`.
  - So a NixOS consumer sets the package explicitly, with
    `.override { hyprland = osConfig.programs.hyprland.package; }`. The
    README shows how.
- It adds the package to `home.packages`.
- **Plugin wiring.** When nixarchy's `programs.nixarchy.plugins` option is
  declared, the module sets `programs.nixarchy.plugins.omateams.src` to the
  packaged plugin.
  - It checks the declared `options`, never `config`, so there is no
    recursion:
    `lib.optionalAttrs (lib.hasAttrByPath [ "programs" "nixarchy" "plugins" ] options) { programs.nixarchy.plugins.omateams.src = ...; }`,
    inside `lib.mkIf cfg.enable`.
  - Without nixarchy, it does nothing more, and the README shows how to point
    Omarchy at the plugin folder.
- The enable-once hook (`local.omarchy.enableOnce`) is the owner's own
  option, so it stays in the owner's host config.

### NixOS module (`programs.omateams`)

- `enable` and `package`, which defaults to the flake package with
  `config.programs.hyprland.package`.
- It adds the package to `environment.systemPackages`.
- This is for systems without home-manager. The plugin wiring is
  home-manager only.

### Consumer change (owner's NixOS config, its own workflow, not this repo)

- Add the `omateams` input (`github:olafkfreund/omateams`) with
  `inputs.nixpkgs.follows = "nixpkgs"`. Don't make `nixpkgs-qt` follow.
- In `hosts/common/nixos/omarchy-omateams.nix`, import
  `omateams.homeManagerModules.default` and set
  `programs.omateams.enable = true` for the user. Keep
  `local.omarchy.enableOnce = [ "omateams" ]` and the existing
  `programs.nixarchy.plugins` path, now set by the module.
- The host config sets `programs.omateams.package` to
  `omateams.packages.${system}.default.override { hyprland = config.programs.hyprland.package; }`.
  `omarchy-omaoutlook.nix` uses that same value, so both use the system
  Hyprland and Teams invitations still open.
- Remove `pkgs/omateams` and its `customPkgs` entry.
- Build p620 and razer. p510 doesn't import omateams; confirm that before
  building and ask the owner before any p510 build.

## Alternatives rejected

- **Overlay only `qt6.qtwebengine` from `master` into the consumer's Qt
  set:** that loads two Qt versions and two glibc builds into one process.
- **Waiting for `nixos-unstable`:** the owner chose to ship now.
- **Nix owning settings (written to `shell.json`, or kept fixed):** the shell
  UI writes these settings, and a fixed copy would fight it.
- **First-run defaults through `manifest.json`:** the shell never reads them
  (see Settings).
- **Fixing `BarWidget.qml` in the source:** the intent rules out changes to
  the app's code. That is a separate change if it is wanted.
- **Putting the enable-once hook in the flake:** it depends on the owner's
  own `local.omarchy` option, and the flake must work without it.
- **A NixOS VM test:** the package checks cover what Nix can see. A VM
  cannot sign in to Teams.

## Risks

- **Two nixpkgs in the closure** until `nixos-unstable` catches up. That
  means extra disk use. Everything is cached, so there is no build cost.
- **`master`'s Qt set breaks** at the pinned revision. Mitigation: pin one
  revision and build it. If the build fails, pick the next cached revision
  that has 6.140.0.
- **A consumer makes `nixpkgs-qt` follow their own nixpkgs.** The version
  assert then fails the build loudly instead of shipping the bug.
- **Hyprland version skew.** `hyprctl` comes from the consumer's Hyprland, as
  today. In the standalone package it comes from `nixpkgs-qt`, which is fine
  for `nix run`.
- **The Qt assert accepts pre-releases of later versions** (for example
  `6.141.0-rc`). That is intended: the fix is in every later branch.

## Verification

- **In this repo:**
  - `nix flake check` passes. It builds the package and runs its install
    checks:
    - the store path in `Service.qml`;
    - all three memory properties and `bash -n` on the wrapper;
    - `install.sh` absent from the plugin;
    - the manifest version.
  - **Qt version.** Show which QtWebEngine the host binary links against:

    ```bash
    nix build .#omateams
    ldd result/bin/.omateams-unscoped-wrapped | grep -o 'qtwebengine-[^/]*' | sort -u
    ```

    Expect `qtwebengine-6.140.0` only.
  - **The assert itself** is checked with `nix eval` over fixed inputs:
    `6.139.0` and `6.140.0-rc` are rejected, and `6.140.0` and `6.140.1` are
    accepted. A moving branch would make the check meaningless once it
    updates.
  - **Module evaluation checks** in `checks`:
    - home-manager with a stub `programs.nixarchy.plugins` option: the
      plugin `src` is set;
    - home-manager without it: it evaluates and sets nothing extra;
    - NixOS: the package is in `systemPackages`;
    - each one with an overridden `package`.
  - Only `x86_64-linux` is built here. `aarch64-linux` is evaluated only,
    and the README says so.
- **In the consumer:**
  - p620 and razer evaluate and build.
  - The omateams in the closure is this flake's package, on QtWebEngine
    6.140.0 (same `ldd` check).
  - `omaoutlook`'s substituted path is the same store path as
    `programs.omateams.package`.
- **Runtime on p620:**
  - The sign-in survives the switch, and existing `shell.json` preferences
    are unchanged.
  - The plugin loads enabled. Teams starts hidden at login, and with
    `runInBackground` off in the shell UI it doesn't.
  - `omateams status` reports the manifest version, and the host is not
    replaced on a plugin reload.
  - `systemctl --user show` on the host's scope shows `MemoryHigh`,
    `MemoryMax` and `MemorySwapMax`.
  - Share and stop 5 times: no `eglCreateSync failed` in the journal, and
    host memory stays flat.
  - A Teams invitation opened from omaoutlook opens in omateams.
